Step 1: Frequency Suffix Tree (FS-Tree)

Finds frequent patterns by building a suffix tree and tracking pattern frequencies.

Python fs_tree.py

    positions = positions_[::]

                continue
            nucl = array[pos + 1]

        # Push branches above cutoff

Step 2: iterate_hints() - Pattern Selection

Groups FS-tree results by length, picks best at each length, detects self-repeating patterns.

Python decompose.py

def iterate_hints(array, fs_tree, depth):
    current_length = 0
    buffer = []
    found_patterns = {}

    for L, names, positions in fs_tree:
        if L != current_length:
            if buffer:
                # Find max frequency in buffer
                max_n, found_seq = max(buffer, key=lambda x: x[2])

                # Check self-repeating
                minimal_unit = is_self_repeating(found_seq)
                if minimal_unit:
                    if minimal_unit not in found_patterns:
                        yield len(minimal_unit), minimal_unit, count
                else:
                    yield current_length, found_seq, max_n

            buffer = []
            current_length = L
            if current_length > depth:
                break
        buffer.append((names[0], positions[0], len(names)))

Step 3: Anchor Graph (Primary Method)

Builds a transition graph where nodes are anchors, edges are transitions between consecutive anchors.

Key Concept: Distance Clustering

If an anchor appears N times per monomer (A-B pattern), distances between consecutive anchor occurrences will form N clusters. True period = sum of cluster centers.

Monomer structure with A-B pattern (anchor appears 2x per monomer): ┌─────────────────────────────────────────┐ │ [ANCHOR]──100bp──[ANCHOR]──240bp──[ANCHOR]──100bp──[ANCHOR]──240bp── │ │ ↑ ↑ ↑ ↑ │ │ region A region B region A region B │ └─────────────────────────────────────────┘ Distances: [100, 240, 100, 240, 100, 240, ...] K-means clustering → 2 clusters: center1=100, center2=240 True period = 100 + 240 = 340bp Cut only at "region A" positions → uniform 340bp monomers

Step 3.5: Anchor Quality Filtering (Rust)

After discovering the chr20_30868954_30881282 problem (Rust chose cut="A", producing 1050 monomers of ~12bp), we added quality filters to reject bad anchors.

The Problem: Single Nucleotide Cuts

Array: chr20_30868954_30881282_12329_171_MONO (12.3 KB) Python decomposition: • Cut sequence: (complex anchor) • Monomers: 8 fragments, ~1540bp each • Problem: monomers too LARGE (should be ~171bp for alpha satellite) Rust decomposition (BEFORE fix): • Cut sequence: "A" (single nucleotide!) • Monomers: 1050 fragments, ~12bp each • Problem: monomers too SMALL and DISSIMILAR Root cause: FS-tree finds "A" is the most frequent pattern (appears ~1050 times). Without filtering, Rust selects it as the anchor. This produces nonsense decomposition — "monomers" are just random chunks between A's, with no biological meaning.

Solution: Two-Tier Quality Filtering

Filter Value Rationale
MIN_ANCHOR_LENGTH 3 bp Single nucleotides (A,C,G,T) and dinucleotides (AT,CG) are too common.
3bp = 64 variants, more specific.
MIN_SIMILARITY 0.5 (50%) Consecutive monomers must share >50% sequence identity.
Random DNA has ~25% similarity by chance (1/4 nucleotides match).

Similarity Check Algorithm

For each anchor candidate: 1. Compute cut positions using cluster analysis 2. Extract sample monomers (up to 10 consecutive pairs) 3. For each pair (monomer_i, monomer_{i+1}): • Calculate Levenshtein edit distance • Similarity = 1 - (edit_distance / max_length) 4. Mean similarity = average of all pairs 5. REJECT anchor if mean_similarity < 0.5 Example - Good anchor "ACGT": Monomers: ACGTNNNN...NNN (171bp each) Edit distance between consecutive: ~25 Similarity: 1 - 25/171 = 0.85 (85%) ✓ PASS Example - Bad anchor "A": Monomers: ACGT (4bp), TGCA (4bp), NNNN (8bp), ... Edit distance between consecutive: ~4 Similarity: 1 - 4/8 = 0.5 (50%) — borderline But lengths vary wildly (4-20bp), so actual similarity ≈ 0.3 ✗ REJECT

    let monomer1 = &sequence[cut_positions[i]..cut_positions[i+1]];
    let monomer2 = &sequence[cut_positions[i+1]..cut_positions[i+2]];

    if monomer1.len() <= MAX_MONOMER_FOR_ED && monomer2.len() <= MAX_MONOMER_FOR_ED {
        let ed = levenshtein(monomer1, monomer2);
        let sim = 1.0 - (ed as f64 / monomer1.len().max(monomer2.len()) as f64);
        similarity_sum += sim;
        count += 1;
    }
}

let mean_similarity = similarity_sum / count as f64;
if mean_similarity < MIN_SIMILARITY {
    continue; // Skip this anchor
}

Why NOT Use MIN_MEAN_MONOMER_LENGTH?

We initially added MIN_MEAN_MONOMER_LENGTH = 20bp, but this would reject legitimate short tandem repeats:
  • Trinucleotide repeats: (CAG)n → 3bp monomers
  • Pentanucleotide repeats: (CAGGG)n → 5bp monomers
  • Microsatellites: various short repeat units
Solution: Rely on similarity check instead. Short but IDENTICAL monomers (similarity=1.0) are valid.
Result: After adding these filters, anchor "A" would be rejected:
  • Length 1bp < MIN_ANCHOR_LENGTH (3bp) → REJECTED
  • Even if we allowed 1bp, similarity would be <0.5 → REJECTED

Quality Metric: Robust CV (MAD / Median)

We use Robust CV instead of regular CV because it's resistant to outliers. One "broken" monomer doesn't ruin the entire array's score.

Regular CV (sensitive to outliers): CV = σ / μ × 100% where μ = mean, σ = std deviation Robust CV (resistant to outliers): RCV = MAD / median × 100% Where: median = middle value when sorted MAD = median(|length_i - median|) ← Median Absolute Deviation Example: Monomers [168, 170, 171, 172, 450] (one outlier) median = 171 deviations = [3, 1, 0, 1, 279] MAD = median([0, 1, 1, 3, 279]) = 1 Regular CV = 53.8% (outlier dominates!) Robust CV = 0.58% (outlier ignored!) Why Robust CV is better: • Scale-invariant: 170bp and 2300bp arrays comparable • Outlier-resistant: one bad monomer doesn't skew results • Uses median: more representative of "typical" monomer Interpretation: RCV ≤ 5% → Excellent (uniform monomers) RCV 5-20% → Moderate (acceptable) RCV > 20% → Poor (needs review)

Edit Distance Analysis: Consecutive Monomer Similarity

A sanity check: consecutive monomers in a satellite array should be similar to each other (they are copies of the same repeat unit with mutations). We calculate Levenshtein edit distance between each pair of consecutive monomers.

Why Edit Distance Matters

Good decomposition: Monomer i: ACGTACGT...ACGT (171bp) Monomer i+1: ACGTACGT...ACGT (171bp) ← few mutations Edit distance: ~10-30 (point mutations only) Bad decomposition (merged monomers): Monomer i: ACGTACGT...ACGT (171bp) Monomer i+1: ACGTACGT...ACGTACGT...ACGT (342bp) ← two monomers merged Edit distance: ~170 (almost full monomer difference!) Expected: • Low mean ED → monomers are similar (correct decomposition) • Low CV of ED → consistent similarity (no outliers) • High CV → some pairs have huge ED (merged/split errors)
